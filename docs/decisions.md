# 決定記録
決めたこと・理由・日付。変える場合は消さずに、新しい番号で追記する。

## D-001 .vwx は直接解析しない(2026-11-22)
- 仕様は非公開のバイナリ形式。専門の変換ソフト(FME)すら対応していない。毎年形式が変わるので、解析は毎年やり直しになる。使用許諾契約の問題もある。

## D-002 取り込みの経路(2026-11-22)
- Vectorworks ユーザー(自分を含む): Vectorworks 用スクリプト(tools/vw-export)で VectorStation 形式に書き出してもらう。スクリプトは本体と並ぶ成果物として扱う。
- AutoCAD・JW-CAD など: DXF / DWG / IFC で読み込む。
- ネイティブ形式は独自(仮: .vws)。formatVersion と移行処理で、バージョンダウンの概念をなくす。
- 未決定: 逆方向(VectorStation → Vectorworks)のスクリプト。Phase 7 で判断。

## D-003 技術基盤は Rust・Craft方式(2026-11-22)
- 中核を1つ作り、ローカル版(Windows / macOS)とブラウザ版(WebAssembly)の両方に載せる。ローカル版が先。
- 理由: 描画性能、Win/Mac 両対応。作成者はどの言語でもコードを読まないため、言語の読みやすさは判断材料にしない。Rust はコンパイル時に間違いを厳しく止めるので、AIの書き間違いが表に出やすい。
- 開発は Windows。Mac 版はビルドを自動化し、動作確認は作成者の Mac で行う。

## D-006 クリーンルームの徹底(2026-11-22)
- Vectorworks の本体を逆アセンブルしたり、内部コードを見たりはしない。材料は公開仕様・マニュアル・スクリプトAPIの公開説明・操作感と挙動の観察だけ。中身はゼロから書く。
- 作成者の Vectorworks 2023 Architect を観察してよい。
- 補足: 最初の Grok との会話ログにあった「内部コードを材料にする」は誤りで、作成者が訂正した。

## D-007 データモデル v1.0 確定(2026-11-22)
- docs/design/data-model.md。作成者の回答(単位 mm、模様・ハッチング・タイル・透明度を使う、グレー表示を使う、1ファイルが理想だが分割もある、並び順をドラッグで変える)を反映。

## D-008 新しく描いた図形の既定の属性(2026-11-22)
- 「作成時にクラスの属性を使う」がオフのクラスで描いた図形は、Vectorworks と同じく属性パレットの現在の設定を使う。画面を作るとき(Phase 2〜3)に実装する。それまでは固定の既定値(黒の実線 0.13mm、白の面)。
- 作成者の方針: 機能もUIも、基本的にすべて Vectorworks と同じにする。
