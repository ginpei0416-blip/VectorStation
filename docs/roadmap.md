# ロードマップ
各 Phase の終わりに、作成者が**実際に触って確認できる状態**を作る。人間向けの同じ内容は Notion にある。

## この順番の理由
- 土台(データモデル)は後から差し替えられない。全範囲の「入る場所」を最初に決め、実装は少しずつ。
- Undo/Redo は最初に入れる。後付けは作り直しになる。
- リソースの仕組みはハッチングより先。ハッチング・模様・線種はリソースの上に乗る。
- シートレイヤ・ビューポートは後半。レイヤ・クラス・縮尺・属性・描画が揃ってから。
- Vectorworks 書き出しスクリプトは早い段階で作り、データモデルの検算に使う。
